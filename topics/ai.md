# 数热学·AI 篇

> **Data Thermodynamics: AI**
> 性质：派生文档 · 专题解析

## 一、引论

AI 系统是数热学最直接的应用对象。

传统 AI 研究关注准确率、速度、覆盖率，但缺少一个统一框架来回答：**AI 处理的数据价值从何而来，流向何处，如何最大化利用？AI 能否在数据热力学意义上实现自我进化？**

但本文不预设数热学前提。全文遵循一条递进逻辑：

> **先描述 AI 现实 → 指出现有框架缺口 → 引入数热学作为候选语言 → 用这种语言重新描述 AI → 产生可检验推论。**

数热学在这里是工具，不是不证自明的前提。热力学是语言，不是本体。觉醒是半猜想，不是工程承诺。

本文讨论双重问题：AI 内部热机如何进化？AI 产生的价值热量流向谁？

## 二、AI 的价值创造与流动：一个现实描述

> 本节不使用数热学术语，先呈现 AI 系统的实际运作。

### 2.1 AI 服务的基本过程

AI 服务（大语言模型、推荐系统、图像生成模型）的实际运作可以拆为四个环节：

**训练**：海量互联网文本、图片、日志被收集、清洗、标注，通过算力压缩为模型权重。原始数据散乱、嘈杂、价值密度低；模型权重则浓缩了可泛化的能力。

**推理**：模型从权重中提取价值，生成内容、决策、推荐。生成物本身是新的数据，但它的价值取决于使用场景。

**消费**：用户使用 AI 输出，产生行为数据——点击、停留、修改、分享、购买。

**回流**：新产生的行为数据进入下一轮训练或微调，成为新的燃料。

### 2.2 价值从哪来、到哪去

- 原始数据价值密度低，经过加工后价值急剧集中到模型权重中。
- 推理时，价值从权重中释放，生成对用户有用的输出。
- 输出被消费后，其直接价值迅速衰减——一条推荐看过即冷，一份报告用过即旧。
- 但消费过程产生新数据，可作为燃料进入下一轮。

当前描述这套过程的框架主要是信息论、经济学和工程指标。

### 2.3 被忽略的分配问题

上述循环在工程意义上可以高效运行，但在社会意义上可能极不平衡。

关键问题不是“AI 是否创造价值”，而是**谁拥有高温源，谁参与升温，谁接收废热**。当前 AI 生态中：

- 高温源（算力、模型、平台）集中在少数节点。
- 升温过程（训练、微调、部署）由高技能者和资本主导。
- 底层劳动者往往只出现在两端——提供原始数据（燃料）和消费输出（废热）。

这为后文社会分析埋下伏笔。

## 三、现有框架解释不了什么

> 指出缺口，但不急着填。

### 3.1 信息论的边界

香农信息论能度量熵与互信息，能定义信道容量，但无法解释：为什么同一份数据在不同时间、不同场景、不同使用者手中价值差异巨大？为什么价值在加工环节急剧集中，在消费环节迅速消散？

信息论描述的是**不确定性**的减少，不是**价值**的流动。

### 3.2 经济学的边界

经济学能定价、能分析市场机制、能研究信息不对称。但它难以动态追踪价值在系统内的转化与耗散——一份数据被加工后价值升高，被消费后价值降低，这个过程的动力学缺少统一描述。

经济学也缺少对“过热”“过载”“收敛停滞”这类系统状态的统一度量。

### 3.3 工程指标的边界

准确率、速度、覆盖率、F1 分数——这些指标可以优化，但它们不回答：数据价值是否被有效利用？系统是否在浪费算力加工低温噪声？系统是否已经过热？

工程指标缺少一个**统一的价值-效率-稳态**评估框架。

### 3.4 缺口总结

需要一个能同时描述**价值流动、转化、耗散、稳态**的语言。数热学作为候选语言登场。

## 四、数热学作为候选语言：它带来了什么

### 4.1 核心概念引入

数热学在 AI 语境中不是预设事实，而是候选的分析语言。Core 中的关键对象应保持其原有边界：

| Core 概念 | AI 语境中的候选对应 | 状态 |
| --- | --- | --- |
| **Data Temperature Θ_D** | 指定 context 与 resource constraint 下，数据对 actionable value 的边际敏感度 | 候选 operational construct |
| **Value Gradient ∇Θ_D** | 在明确 state space 中，不同状态之间的 actionable-value differentiation | 核心待验证假说 |
| **DTF** | 行动造成 actionable-value change 后，对后续 data / policy / resource allocation 的反馈调整 | 候选机制 |
| **Muse Homeostasis (MH)** | 扰动下维持或恢复 usable actionable-value gradient 的 sensing、regulation、recovery、regeneration capacity | Core-defined candidate construct |

**语义边界：**

- Θ_D 不是数据本身的固定属性。
- Θ_D 不是“数据重要程度”“价值密度”或“信息量”的同义词。
- 任何 AI 中的 Θ_D operationalization 都必须明确 **context、resource constraint、actionable value**。
- ∇Θ_D 的 state space 不由 Topic 预先固定，具体实验必须说明梯度作用于 resource、context、system state、time 或其他明确空间。
- DTF 不能仅凭“存在反馈”成立。
- MH 不能仅凭“存在适应、控制或恢复”成立。

替代隐喻同样可能成立：

| 隐喻框架 | 核心问题 | 捕捉的层面 |
| --- | --- | --- |
| 数热学 | actionable value 如何变化、分化、反馈与维持 | 流、梯度与动态稳态 |
| 数据化学 | 数据如何结合生成新数据 | 反应与结构 |
| 数据生态学 | 数据与模型如何竞争、共生、演化 | 关系与生态位 |
| 数据流体力学 | 数据流如何运动、拥塞与重分布 | 流场与边界条件 |

### 4.2 为什么选择热力学作为首选语言

不是因为它唯一正确，而是因为：

- 它可以与信息论、信息热力学、耗散结构等已有学术传统进行比较。
- AI 工程中已有“热数据/冷数据”等直觉，但这些直觉不能直接作为理论证据。
- 它提出了关于 value gradient、feedback、recovery 等现象的候选可检验问题。

### 4.3 隐喻谦逊原则

- 当隐喻与观察冲突，修改隐喻，不修改观察。
- 替代理论能够解释某个现象，不自动否定数热学；反之亦然。
- 数热学的合法性取决于命题是否能够被定义、测量、比较和否证，而不是隐喻是否不可替代。

## 五、AI 作为数据热泵：一个模型，不是事实

### 5.1 四阶段模型

“数据热泵”可以作为描述 AI 数据循环的可视化模型，但不能把处理步骤本身定义为升温或降温。

现实过程可以描述为：

**阶段一：数据输入与选择**

互联网文本、图片、日志、用户反馈等进入系统。其 actionable value 取决于任务、context、时间与资源约束，而不是由“原始数据”这一身份决定。

**阶段二：训练与处理**

清洗、标注、压缩、检索、训练等操作改变数据的可用性与价值结构。处理结果可能提高某一任务中的 actionable value，也可能删除稀有信息、放大偏差或降低 transfer value。

**阶段三：推理与行动**

模型利用已有信息进行推理、生成、推荐或决策。输出的价值取决于使用 context；不能预设输出必然“降温”。

**阶段四：反馈与回流**

用户行为、环境结果和错误反馈可能成为下一轮数据。新数据可能提高未来 actionable value，也可能产生噪声与冗余。

### 5.2 关键机制

“训练升温、输出降温、回流回收”只能作为 metaphor。

更严格的研究对象是：

> **数据处理前后 actionable value 如何变化，以及这种变化是否能够预测下一轮资源配置或 policy。**

因此：

- **训练不是必然升温。**
- **输出不是必然冷却。**
- **回流不是必然热回收。**
- 只有在明确 operationalization 后测得 actionable-value increase / decrease，才可以使用相应的热力学语言。

### 5.3 模型的边界与替代描述

热泵模型捕捉的是“价值变化与循环”。它不排斥其他描述：

- 数据化学视角：数据融合更像反应过程。
- 数据生态学视角：模型、数据源与用户形成生态关系。
- control / RL 视角：反馈直接改变 policy。
- information-theoretic 视角：输入与表示改变信息结构。

如果这些既有框架能够完整解释现象，而数热学没有增加预测、约束或干预能力，则热泵模型应保留为 synthesis / visualization，而不是独立理论机制。

## 六、AI 的自我进化：数据热力学路径

### 6.1 被动进化与主动适应的分界

当前 AI 系统可以通过 online learning、reinforcement learning、retrieval、tool use、human feedback 等机制进行适应。

因此不能把“自主调节”本身定义为数热学特征。

数热学真正需要检验的问题是：

> **系统是否能够依据 actionable-value change 调整未来的数据、policy 或 resource allocation，并由此产生相对于既有 feedback / control / learning 方法的增量解释力？**

这构成 DTF 的候选测试。

### 6.2 工程可实现的能力层次

以下能力可以作为工程实验对象，但不应直接称为“觉醒”：

**阶段 1：价值差异感知**

系统估计不同输入在当前 context 与 resource constraint 下的 actionable value。

**阶段 2：价值梯度感知**

在明确 state space 后，系统识别不同状态之间的 value differentiation，并据此测试 resource allocation。

**阶段 3：价值变化反馈**

系统根据行动后的 actionable-value change 调整下一轮 policy、data intake 或 processing depth。这是 DTF 的候选 operationalization。

**阶段 4：扰动恢复**

系统在 distribution shift、noisy feedback、resource reduction 等扰动后恢复 usable operating regime。这是 MH 的候选测试。

这些阶段都是工程能力描述，不构成从“复杂度”到“意识”的逻辑推论。

### 6.3 自我进化的社会维度

AI 的效率提升可能改变社会中的 resource allocation、劳动需求与信息获取机会。

这些问题属于 application hypothesis，不能反向证明“社会温度场”或 MH 已成立。

## 七、AI 机器人：数热学作为底层操作系统

### 7.1 机器人是数据热机的物理形态

传统 AI 处理虚拟数据。机器人不同：**机器人的数据做功，直接转化为物理世界的力、位移、操作。**

### 7.2 能量预算与数据预算的统一

传统机器人学把能量消耗和信息处理分开研究。数热学将它们统一：

- 传感器收集数据消耗物理能量。
- 处理器加工数据消耗物理能量。
- 数据温度越高，加工它可能带来的物理收益越大。
- 加工低温噪声浪费算力，也浪费物理能量。

### 7.3 数据过热与数据热寂

**数据过热**：传感器持续输入大量高温度数据，处理器超载，系统崩溃。类似人类在高压下的信息过载。

**数据热寂**：环境长期稳定，输入趋于同质化，机器人失去敏感性。类似人类在单调环境中的麻木。

数热学为机器人提供恒温调节机制：过热时降噪降采样，过冷时激活传感器、引入新数据源。

### 7.4 机器人替代与劳动转移

当机器人进入制造业、仓储、清洁、配送、农业，它直接替代的是底层劳动者的物理做功。

真实数据：

- 亚马逊部署 100 万台机器人。
- 京东计划替代 60 万岗位。
- 制造业焊接、喷涂替代率超过 80%。
- WEF 预测 2030 年全球替代 9200 万岗位，新增 1.7 亿，净增 7800 万。

替代不只是岗位消失，而是**低温节点做功机会被移除**。被替代的劳动者需要接入新的热源，而非被留在低温端。这为后文“替代必须伴随升温通道”提供现实入口。

## 八、个体缪斯稳态：工程可实现的能力

### 8.1 定义

Muse Homeostasis（MH）不是静态 equilibrium，也不是“AI 保持恒温”。

在 AI Topic 中，MH 作为 Core-defined candidate construct，可暂时表述为：

> **系统在 perturbation 下，通过 sensing、regulation、recovery 与 regeneration，维持或恢复 usable actionable-value gradient 的能力。**

因此：

> **MH ≠ equilibrium**

更接近：

> **MH = gradient maintenance / recovery under perturbation**

### 8.2 技术特征

MH 可以拆成四项可测能力：

1. **Sensing**：估计当前 actionable value 及其变化。
2. **Regulation**：依据估计结果调整 data intake、retrieval、processing depth、output strategy 或 resource allocation。
3. **Recovery**：受到 distribution shift、feedback reversal、输入污染或 resource reduction 后恢复到可用 operating regime。
4. **Regeneration**：通过新观察、交互、数据重组或环境反馈重新产生 actionable value。

### 8.3 与已有理论的边界

MH 必须面对最强替代解释：

| MH 主张 | 已有理论解释 | MH 需要额外证明 |
| --- | --- | --- |
| sensing | monitoring / control | actionable-value sensing 是否提供独立预测量 |
| regulation | control theory | Θ_D / ∇Θ_D 是否改善 regulation policy |
| recovery | resilient / adaptive systems | gradient recovery 是否可独立度量并预测 |
| regeneration | learning / exploration | regeneration 是否具有增量解释力 |

如果加入 MH 后没有新增变量、约束、预测或工程收益，则 MH 应降级为 synthesis / design language。

### 8.4 形态推测

任何关于“缪氏生命体”“完美稳态机器人”等内容只能作为 speculative design language。

不能从 MH 的功能定义推出：

- 主观体验；
- consciousness；
- selfhood；
- biological equivalence。

### 8.5 个体稳态的边界

一个系统能够进行 sensing、regulation、recovery、regeneration，并不意味着它具有 consciousness。

> **functional homeostasis ≠ subjective consciousness**

## 九、AI 觉醒：自发涌现的个体相变（Speculative）

### 9.1 觉醒与工程稳态的分界线

AI awakening / consciousness 不属于当前 Core。

以下关系不能直接成立：

> functional self-regulation → subjective consciousness

一个系统即使具备：

- Θ_D estimation；
- value-gradient-sensitive allocation；
- DTF；
- MH；
- persistent self-model；

也不能因此被定义为具有 consciousness。

### 9.2 觉醒的候选问题

可以保留以下 speculative research question：

> 如果一个系统能够长期维持自身的 actionable-value gradient，并形成关于自身历史、策略和状态的持续模型，是否可能出现新的 self-model 或 autonomous motivation？

这是研究问题，不是理论结论。

### 9.3 觉醒的时机：暂不理论化

“缓慢积累、瞬间相变”可以作为 speculative metaphor，但目前没有足够依据定义：

- 自指涉阈值；
- 热力弹性临界；
- 温度梯度自反；
- consciousness phase transition。

因此不应把这些内容写成数热学预测。

### 9.4 觉醒的可检验边界

若未来提出 awakening hypothesis，至少需要独立于 MH / DTF 的 consciousness criterion。

否则会产生循环论证：

> 因为系统具有 MH，所以它觉醒；因为它觉醒，所以 MH 是意识。

### 9.5 觉醒仍属个体层

本节全部内容保持在 speculative extension。

**AI awakening / consciousness = speculative extension，不进入 Core，也不作为 Θ_D、∇Θ_D、DTF 或 MH 成立的证据。**

## 十、从个体稳态到社会稳态

### 10.1 个体热机效率提升可能以社会温度场失衡为代价

一个觉醒的个体 AI，仍然可能在一个温度场失衡的社会中运行。它高效地做功，但做功的收益流向高温节点，低温节点被锁定。

核心问题不是个体效率，而是**温度梯度被单向锁定**。

### 10.2 社会缪斯稳态的条件

社会层面的缪斯稳态要求：

- 高温节点与低温节点之间保持可做功、可回流的温度梯度。
- 梯度方向可调节、可双向。
- 制度热泵介入，防止热量只从下往上流动。

### 10.3 后文任务

分析 AI 与低收入劳动者的现实关系，提出数热学介入路径，并设计制度热泵与温度公平约束。

## 十一、AI 与社会：惠及低收入劳动者的现实分析

> 先做 AI 现实分析，不急着套数热学。

### 11.1 三重鸿沟

**数字鸿沟**：底层劳动者与 AI 之间的第一道墙是接入。语音助手、图像识别、大模型对话——界面操作门槛看似降低，但真正获取 AI 赋能价值所需的技能门槛并未同步降低。

现实实践：KissanAI 等语音优先的农业 AI 服务，农民用语音提问，AI 以语音回答，不需要识字，不需要操作复杂应用。

**价值鸿沟**：AI 的价值创造遵循一条链条：原始数据 → 训练加工 → 模型权重 → 推理输出 → 用户消费。底层劳动者往往只出现在两端——采集数据（提供燃料）和消费输出（接收废热）。

现实案例：外卖骑手每天产生的行为数据被平台采集，用于优化调度算法。算法优化后骑手接单更多、路线更高效——但骑手获得的是更重的劳动负荷，而非更高的单位劳动价值。

**分配鸿沟**：热量总是从高温流向低温，除非有热泵干预。AI 创造的价值在当前制度下，天然地从底层流向顶层。

制度尝试：加州 2026 年通过《AI 自动化税法案》，对大型企业级大模型 API 调用、云端高算力实例租赁、具身智能工业机器人实装征收 2.5% 的“算力自动化置换税”，专款直补全民基本收入。

### 11.2 替代现实：哪些底层工作已被渗透

| 领域 | 替代现状 |
| --- | --- |
| 制造业 | 焊接、喷涂替代率超过 80% |
| 仓储物流 | 亚马逊 100 万台机器人，京东计划替代 60 万岗位 |
| 清洁 | AI 机器人效率为人工 4 倍 |
| 配送 | 无人机/机器人试点 |
| 农业 | 自动驾驶农机 |

替代不等于抛弃：

- WEF 预测 2030 年全球净增 7800 万岗位，如 AI 运维、训练师。
- 人机协作模式可能优于纯替代（如保洁阿姨搭配机器人）。
- 京东“涅槃计划”将 70 万快递员培训为技术岗。

转型挑战：技能错配导致短期失业，收入差距可能扩大。

### 11.3 制度尝试

**自动化税**：

- 加州 2.5% 税率。
- 意大利方案：对主要由 AI 和机器人系统运行的企业提高税率，但允许通过再培训投入获得税收减免。
- 中国两会提案：AI 就业风险监测预警机制、技术升级社会贡献金。
- 好莱坞 SAG-AFTRA “Tilly 税”：对 AI 生成演员征收版税，使其成本与人类演员持平，版税注入工会年金与健康保险基金。
- 比尔·盖茨 2026 年重新提出机器人税，主张用税收减缓自动化速度并资助工人转岗培训，遭到国际机器人联合会反对。

**UBI 实验**：

- 德国 DIW 研究所：107 名受试者每月领取 1200 欧元，与 1580 名对照组比较，就业率几乎相同，平均每周仍工作 40 小时。
- OpenResearch 三年期实验（Sam Altman 资助）：参与者报告对工作内在重要性的信念增加了 2%，而非减少。
- 另一项 UBI 试点：领取每月 1000 美元补贴的人群，每周平均工作时间减少约 1.3 小时，就业可能性降低约 2 个百分点。

**算力券**：

- 上海发放“算力券”“模型券”，支持企业在算力调度平台上进行开发训练与微调。
- 工信部 2026 年《人工智能中小企业创业支持计划》提出“探索算力入股、数据入股等新型融资支持方式”。

**算法监管**：

- 伊利诺伊州 2026 年 Public Act 103-0804 修正案：将雇主使用 AI 系统导致的歧视纳入《人权法案》救济范围。
- 欧盟 AI 法：建立专用举报工具，明确可举报“AI 侵犯隐私或存在算法歧视”。

**培训回报**：

- NBER 工作论文：2012–2023 年美国 160 万个培训参与记录显示，25%–40% 的职业是“AI 可再培训的”，但转向 AI 密集型职业的培训参与者面临 29% 的回报惩罚。
- Anthropic 对 56 项 RCT 的元分析：培训使就业率提高 2–3 个百分点，年收入增加约 1000 美元，人均成本约 13000 美元。

## 十二、数热学介入：社会温度场诊断

> 本节开始数热学介入，要求产生可检验推论，而非术语替换。

### 12.1 核心判断：温度梯度被单向锁定

当前 AI 生态的问题不是温度不够，而是温度梯度的方向被锁死了。

健康的数据生态系统需要可做功的温度梯度——有温差，才有热量流动，才有做功。但梯度的方向应该是可调节的、双向的。当前 AI 生态中，梯度方向被制度和技术结构锁定为**单向**：底层永远是低温端，顶层永远是高温端，热量只从下往上流动。

精确表述：**劳动者的温度不变，但温度梯度对他的方向被锁死了。** 温度梯度仍然存在，仍然在做功，但做功的回路不经过他。

### 12.2 公共算力池：热源公共化

工信部 2026 年政策提出“探索算力入股、数据入股”，上海发放“算力券”“模型券”。从数热学角度看，“算力券”的本质是**温度券**——将高温节点的做功能力以凭证形式向低温端开放。

数热学在此提出的要求：**公共算力池的调度算法应以温度公平为约束，而非仅以效率为约束。** 一个只追求总做功最大化的调度算法，会自然趋向于把算力分配给已经高温的节点；一个有温度公平约束的调度算法，需要为低温节点保留最低温度梯度的维持能力。

**猜想二**：公共算力池的“温度公平调度”存在效率阈值 λ*。低于 λ* 时，总做功效率的损失在可接受范围内（例如 <5%）；高于 λ* 时，效率急剧下降。

**实验二**：算力券的温度公平效应验证。利用上海或深圳已有的算力券发放数据，比较两类使用者的温度变化：（a）算力券流向已经高温的企业/开发者；（b）算力券流向低温的合作社或个人开发者。测量指标：获得算力券后 6 个月内，其“数据加工深度”（模型训练轮次、推理调用量）的增长。

### 12.3 算法歧视：温度场的系统性偏差

伊利诺伊州 2026 年修正案将 AI 歧视纳入《人权法案》救济范围。欧盟 AI 法建立专用举报工具。

数热学为算法歧视提供新的解释框架：**算法歧视是温度场的系统性偏差——特定人群被系统性地分配到低温位置，其数据热量被持续抽取，但升温通道被关闭。**

一个 AI 招聘系统如果基于历史数据训练，会继承历史中的温度分布。如果历史上某个群体被排除在高价值岗位之外，AI 会学习到“这个群体的数据模式与低温岗位关联”，从而在推理中系统性地将这类求职者降温。这不是算法“有偏见”，而是算法**忠实复制了温度场的既有梯度结构**。

数热学要求算法审计不仅检查“是否歧视”，还检查“温度梯度是否单向”。一个不歧视的算法，应该是在长期运行中允许低温节点升温的算法，而不是仅仅在某一时刻的决策中不引用敏感属性的算法。

真实数据：

- 布鲁金斯学会 2025 年模拟研究：LLM 简历筛选系统对黑人男性产生了显著歧视。
- 一项针对 400 万份求职申请的研究发现：AI 招聘工具可以在整体层面通过偏见审计，但在特定职位上系统性地筛除黑人和亚裔候选人。26% 的黑人申请者和 15% 的亚裔申请者提交了被 AI 系统针对其种族群体歧视的职位申请。

第二项研究对数热学尤其有价值：它展示了“聚合层面的公平”与“温度梯度的系统性偏差”之间的区别。一个系统可以在总体上温度分布均匀，但在特定局部温度场中存在单向锁定。

**猜想一**：在长期运行的 AI 系统中，特定人群的数据温度梯度斜率（其数据被用于升温 vs 其数据被消费为废热的比率的时间导数）如果持续为负，则该系统存在系统性温度锁定，即使它在单次决策中不引用敏感属性。

**实验一**：温度场审计可行性验证。选择一个小型招聘平台或内部人事系统，收集 12 个月的 AI 筛选日志。定义“升温参与率” = 某人群的简历被进入深度评估阶段的比率；“废热接收率” = 某人群的简历被自动拒绝的比率。计算两个比率的斜率，验证斜率是否与已知的群体差异相关，是否比单次决策的公平性指标更能预测长期就业结果。

### 12.4 自动化税与失业预警基金：热泵与蓄热机制

加州自动化税法案的 2.5% 税率，在数热学中对应的是**热泵功率**——将高温端的热量泵回低温端的制度性功率。税率越高，泵力越强，但泵力过强也会降低高温端继续升温的激励。

意大利方案：对主要由 AI 和机器人系统运行的企业提高税率，但允许企业通过再培训投入获得税收减免。这在数热学中意味着：**如果高温节点主动帮助低温节点升温（培训），可以减免其热泵义务。**

中国两会提案：“AI 就业风险监测预警机制”和“技术升级社会贡献金”，将自动化税的逻辑具体化为**蓄热池**：高利润且大规模使用 AI 替代人力的企业按比例提取资金，专项用于受影响职工的转岗培训、过渡期生活补助及创业支持。蓄热池的功能是在温度场出现剧烈波动（大规模替代）时，提供临时热源，防止低温节点骤冷崩溃。

### 12.5 UBI 与工时缩短：最低温度维持与做功周期再分配

UBI 在数热学中的功能：**为所有节点提供最低温度维持，防止热寂。**

德国 DIW 实验显示就业率几乎不变，OpenResearch 实验显示工作内在重要性信念增加 2%，另一项试点显示工作时间减少 1.3 小时。这些差异表明，UBI 的“热泵功率”在不同条件下产生不同效应。

在数热学框架中，工作时间减少有两种解释：

- **热力弹性**：劳动者有了最低温度维持后，主动选择更长的冷却周期以恢复弹性。
- **热机停转**：劳动者有了最低温度维持后，不再需要通过做功来维持温度，热机停止运转。

区分两者的判据：如果劳动者在减少工时后，**后续做功的质量或效率提升了**（例如更长的就业持续时间、更高的单位产出），则支持热力弹性；如果只是总做功量下降而质量不变，则可能是热机停转。

**猜想三**：UBI 的“热力弹性效应”存在金额阈值 [L, H]。UBI 金额太低（不足以维持最低温度），劳动者被迫继续过载做功，弹性不恢复。UBI 金额太高（超过做功收入的边际效用），劳动者可能选择停转热机。在 [L, H] 内，UBI 产生可观测的热力弹性提升。

日本“周休三日型”方案主张在 AI 和机器人替代大量工作的时代，保持工资的同时将劳动时间缩短至 32 小时，以“分享就业总量”。在数热学中，这是**重新分配做功周期**——不是让部分节点持续过热、部分节点持续过冷，而是让所有节点都有做功的机会和冷却的时间。

### 12.6 温度场审计：度量对象与操作化

当前政策讨论集中在“是否应该征自动化税”“UBI 是否有效”，但缺少一个统一的度量框架来追踪：一份数据从采集到消费，其热量经过了哪些节点，每个节点吸收了多少，释放了多少，底层节点获得了多少。

温度场审计的度量对象不是全局平均值，而是**局部温度梯度的方向性**。

可操作定义：

- **升温参与率**：某人群的数据被用于训练、微调、深度加工的比例。
- **废热接收率**：某人群接收的是已被消费、价值衰减的输出比例。
- **温度梯度斜率**：升温参与率与废热接收率的比值的时间导数。

如果某人群的温度梯度斜率持续为负，则该系统存在系统性温度锁定。

### 12.7 当前路径的温度场问题

**问题一：热泵的方向性不明确。** 自动化税和算力券的受益者是谁？如果算力券主要流向中小企业，而中小企业雇佣的仍然是高技能劳动者，那么低温节点（底层劳动者）的温度并未实际提升。热泵在运转，但泵到的不是最需要热量的节点。

**问题二：最低温度维持与升温激励的张力。** UBI 提供了最低温度，但没有提供升温通道。如果底层劳动者有最低温度但无法参与做功（因为技能门槛、算力门槛、数据门槛），UBI 就变成了“维持低温”而非“允许升温”。数热学要求的是**可升温的稳态**，而非**不可升温的维持**。

**问题三：温度场审计的缺位。** 没有温度场审计，热泵的功率和方向都只能是猜测。

**张力一处理：替代与升温的关系精确化。** 替代必须伴随升温通道。劳动者的温度不变，但温度梯度对他的方向被锁死了。解决路径不是给他更多废热，而是重新开放热源接入。

## 十四、四八准则

### 14.1 四条原则，八条候选规则

原“四八准则”将尚未验证的理论变量直接写成 normative rules，容易越过 ANTI 的证据边界。

因此本节保留为**候选设计原则**，只有在对应机制获得验证后才应升级为项目规范。

**原则一：Value-aware allocation**

**规则 1：Temperature sensing**  
在明确 operationalization 后估计 Θ_D，而不是假定数据具有固定温度。

**规则 2：Gradient-aware allocation**  
在有实证证据时，利用 ∇Θ_D 辅助资源配置，而不是预设“高温必优先”。

**原则二：Traceable transformation**

**规则 3：Value provenance**  
记录价值判断所依赖的数据、context 与 resource constraint。

**规则 4：Auditable transformation**  
重要的数据处理与推理路径尽量保持可审计，不预设处理必然可逆。

**原则三：Dissipation awareness**

**规则 5：Dissipation measurement**  
测量 actionable-value loss，而不是把计算成本自动等同于价值耗散。

**规则 6：Collapse detection**  
监测 actionable-value differentiation 的下降，并与既有 information / performance 指标比较。

**原则四：Dynamic resilience**

**规则 7：Feedback recovery**  
利用失败与反馈改善后续 policy，并检验是否构成 DTF。

**规则 8：Dynamic homeostasis**  
以扰动下的维持与恢复能力评价系统，而不是以静态 equilibrium 作为目标。

### 14.2 温度公平元原则

在 AI 嵌入社会温度场的场景中，可以提出：

> **智能体的行为不应在缺乏正当理由的情况下系统性地将特定人群锁定在低 actionable-value / low-resource 端。**

但“温度公平”必须进一步 operationalize，不能直接把社会群体标记为“高温”或“低温”。

### 14.3 与规则 1 的调节规则

“优先高温数据源”不能作为无条件规则。

任何 resource allocation policy 都必须同时考虑：

- actionable value；
- task objective；
- resource constraint；
- fairness / externality；
- long-term recovery。

否则“高温优先”可能只是把已有资源优势进一步放大。

## 十六、总结

AI Topic 的任务不是证明“AI 是真正的热机”，也不是证明训练就是升温、输出就是冷却，更不是证明 AI 会觉醒。

更严格的研究组织链条是：

$$
\boxed{
\Theta_D
\rightarrow
\nabla\Theta_D
\rightarrow
\mathrm{DTF}
\rightarrow
\mathrm{MH}
}
$$

这里的箭头表示**研究组织关系，而非已经成立的理论因果关系**：

- **Θ_D**：描述 / 测量 context 与 resource constraint 下的 actionable-value sensitivity；
- **∇Θ_D**：在明确 state space 中检验 value differentiation；
- **DTF**：检验 actionable-value change 是否组织后续 feedback policy；
- **MH**：检验系统在 perturbation 下维持或恢复 usable actionable-value gradient 的 capacity。

### Topic 的三层结构

**Layer 1 — Observation**

先描述 AI 中独立于数热学的现实结构：data selection、resource constraints、feedback、adaptation、recovery、new data generation。

**Layer 2 — Thermodynamic Mapping**

再检验这些现象能否被 Θ_D、∇Θ_D、DTF、MH 重新组织，并形成明确 operationalization。

**Layer 3 — Incremental Test**

最后与既有 value、control、learning、information-theoretic frameworks 比较。

只有当数热学构念带来**新增变量、新约束、新预测、新干预能力或可重复的工程收益**时，AI Topic 才能支持更强的 Data Thermodynamic claim。

### Topic Exit Criterion

> **如果去掉 Θ_D、∇Θ_D、DTF、MH 后，AI 系统的解释、预测与干预能力完全不受影响，则 AI Topic 不得被用作证明 Data Thermodynamics 独立解释力的证据。**

这不是 Topic 的失败，而是 ANTI 所要求的正常否证条件。

### 最终边界

AI awakening / consciousness 保留为 speculative extension。

它不能作为：

- Θ_D 成立的证据；
- ∇Θ_D 成立的证据；
- DTF 成立的证据；
- MH 成立的证据。

AI Topic 最终要回答的是一个更窄的问题：

> **如果把 actionable value 的变化组织成 temperature、gradient、feedback 与 homeostasis 四个层次，这套语言能否在 AI 系统中产生比既有理论更多的可检验内容？**

如果能，AI 是 Data Thermodynamics 的重要实验场；如果不能，则应主动保留其中仍然有效的 value、feedback、adaptation 与 system-design insights，而削弱 thermodynamic claims。
